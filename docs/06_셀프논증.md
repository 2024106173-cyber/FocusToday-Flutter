# 6. 셀프 논증 기록 · 초안, 발표자 확인 필요

작성 기준: 2026-10-28 / 반론 생성 도구: ChatGPT

**중요:** 아래 '나의 재반박'은 학생이 동의 여부를 판단하도록 작성한 **검토용 초안**이다. 실제 사고를 했다고 가장하지 않으며, 발표자가 근거를 재확인하고 선택을 확정해야 한다.

## 쟁점 1. 색상으로 카테고리 구분

**내 최초 주장:** Google Tasks 공개 리뷰 2건이 모바일 색상 구분을 요구했으므로, 작업마다 카테고리 색을 표시해야 한다.

**AI 반론:** 색만으로 구별하면 색각 차이가 있는 사용자에게는 불리하다. 색상 요구가 있다고 해서 색을 넣는 것만으로 탐색 문제가 해결된다는 보장은 없다.

**나의 재반박(검토용):** 색을 없애는 대신 색+텍스트를 병행해야 한다. 학교/생활/개인 라벨을 항상 쓰고, 카테고리별 색을 일정하게 유지하면 한 요소를 놓쳐도 의미를 알 수 있다.

**재검토와 결정:** 수정. '색상만'에서 **색상 + 텍스트 라벨**로 설계 기준 변경.

**근거:** R01·R02의 카테고리 시각 구분 요구, G1·G2 접근성 원칙.

**전후 비교:** 이전 시안 = 색 점만 표시 / 최종 시안 = 색 점 옆에 '학교·생활·개인' 문자.

## 쟁점 2. 우선순위 자동 추천 AI

**내 최초 주장:** 사용자가 할 일을 입력하면 AI가 자동으로 우선순위를 추천하게 하자.

**AI 반론:** 추천 근거가 불명확하면 사용자는 결과를 신뢰하기 어렵다. 실제 AI 연동은 외부 API·개인정보·비즈니스 로직을 수반하며 UI 전용 과제 범위를 넘어선다.

**나의 재반박(검토용):** 이번 프로젝트의 핵심은 빠른 스캔이다. 우선순위는 사용자가 명시적으로 선택하고, 화면이 그 결정을 명료하게 보여 주면 충분하다.

**재검토와 결정:** 폐기. AI 자동 분류/추천은 구현하지 않음. 빠른 추가 BottomSheet의 수동 우선순위 선택으로 대체.

**근거:** 과제의 허용 UI 범위 및 5 Why에서 선택한 단일 문제.

**전후 비교:** 이전 시안 = AI 추천 버튼 추가 / 최종 시안 = 높음·보통·낮음 ChoiceChip.

## 쟁점 3. 완료 처리의 피드백

**내 최초 주장:** 체크박스를 누르면 항목을 즉시 목록에서 숨기자.

**AI 반론:** 실수로 완료한 작업을 찾지 못하면 손실 불안이 생긴다. 상태 변화에 대한 피드백과 되돌리기가 있어야 한다.

**나의 재반박(검토용):** 완료 상태를 표시하면서 별도 완료함 탭에 그대로 남기고, SnackBar에 실행 취소를 제공한다면 UI가 가역적이다.

**재검토와 결정:** 수정. 완료함 + 완료 취소 + 실행 취소 SnackBar 채택.

**근거:** 일반적 UI 가역성 원칙. 이 문제에 대한 직접 Google Tasks 리뷰는 확보하지 못했으므로 **증거가 아닌 설계 보완 가설**이다.

**전후 비교:** 이전 시안 = 체크 시 화면에서만 사라짐 / 최종 시안 = 완료함에서 재확인 및 복구.

## 쟁점 4. 효과를 어떻게 주장할 것인가

**내 최초 주장:** v2는 기존 앱보다 분명히 더 사용하기 쉽다.

**AI 반론:** 리뷰 3건과 가상 여정만으로 개선 효과를 증명할 수 없다. A/B 테스트나 실제 사용자 과제가 없다.

**나의 재반박(검토용):** 발표는 성공을 확정해 말하지 않고 '리뷰에 근거한 UI 가설과 테스트 계획'으로 표현해야 한다. 대상 찾기 시간과 정확도를 후속 검증 지표로 제안하자.

**재검토와 결정:** 유지하되 주장 수준을 축소. **효과 확인 전의 프로토타입**이라고 명시.

**근거:** 자료의 수집 범위와 후속 테스트 계획.
