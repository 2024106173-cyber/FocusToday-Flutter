# 4. 피쉬본 + 5 Why

## 선택한 한 가지 우선 문제

모바일에서 서로 다른 목록의 작업을 빠르게 구분하기 어렵다. 증거는 R01(2026-05-20)과 R02(2026-08-27)의 시각 구분 개선 요청이다. 아래 원인은 직접 측정되지 않은 **기획 가설**이다.

## 피쉬본 원인 후보

| 분야 | 가설적 원인 | 근거 |
|---|---|---|
| 정보 구조 | 카테고리 정보가 작업 제목과 분리 | 가설 |
| 시각 언어 | 목록 구분 단서 부족 | R01·R02 요구에서 착안 |
| 환경 | 이동 중 짧은 시간에 탐색 | 페르소나 가정 |
| 작업 특성 | 학교와 개인 항목을 함께 관리 | 이용 맥락 가정 |
| 상호작용 | 맥락 확인에 추가 탭 필요 가능성 | 미검증 |
| 접근성 | 색만으로 의미 전달하면 오류 위험 | UX 설계 고려 |

## 5 Why

1. 왜 구분이 어려울까? 작업의 소속 맥락을 즉시 인지할 단서가 약할 수 있다.
2. 왜 단서가 약할까? 작업명과 날짜에 비해 카테고리 식별 정보가 덜 눈에 띌 수 있다.
3. 왜 그럴까? 작업 입력/관리와 별개로 짧은 시간의 목록 스캔 경험이 충분히 강조되지 않았을 수 있다.
4. 왜 스캔이 중요한가? 사용자는 서로 다른 용도의 항목을 한 화면에서 비교한다.
5. 왜 불편이 반복되는가? 각 작업 행에서 맥락과 중요도를 일정한 방식으로 부호화하지 않았기 때문이라는 가설을 세운다.

## 가장 먼저 바꿀 1개

작업 카드의 **카테고리 텍스트 + 일관된 색상 + 우선순위 문자**를 상시 노출한다. 색만으로 구분하지 않는다.

## 제외한 기능

실제 다중 알람, 클라우드 동기화, AI 자동 추천, 영구 저장은 수업 UI 범위를 넘으므로 구현하지 않는다.
