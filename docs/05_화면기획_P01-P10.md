# 5. 화면 기획 · P01~P10

## IA와 네비게이션

앱 이름: 오늘한눈. 일관된 하단 NavigationBar(오늘/전체/예정/완료함)에서 주요 작업 상태에 도달한다. 상세 화면은 Navigator.push/pop, 빠른 추가와 필터는 showModalBottomSheet로 연다. 상단 더보기 메뉴로 세 가지 상태 화면을 재현한다.

## 디자인 원칙

- **G1. 맥락:** 모든 항목에서 카테고리 색과 텍스트를 함께 제공
- **G2. 우선순위:** 긴급도는 색에만 의존하지 않고 '높음/보통/낮음' 표기
- **G3. 가역성:** 완료/완료 취소가 가능하고 완료함에서 재확인
- **G4. 상태 투명성:** GET 로딩/오류/빈 화면을 명시적으로 표시
- **G5. 범위 준수:** 버튼은 UI 상태만 전환하며 DB에 저장하지 않음

P08~P10의 상태를 화면 ID로 분리하여 설명하되 별도 복잡한 상태관리 라이브러리는 사용하지 않는다.

## 인터랙션 규칙

1. 초기 로드: local json-server의 GET /tasks를 호출한다.
2. 요청 실패: 이유가 있는 에러 화면과 '다시 시도' 표시.
3. 완료 탭: 화면 내 TaskData.completed 토글, SnackBar에 실행 취소.
4. 완료함 탭: 완료한 작업을 유지하며 재진입과 되돌림 지원.
5. 빠른 추가: 입력값이 비어 있으면 경고, 유효하면 임시 로컬 카드 추가.
6. 색각 다양성 대응: 학교/생활/개인 **글자**를 색과 병행.
7. 넓은 화면: 최대 가로 너비 제한으로 태블릿에서도 가독성 확보.

## 화면 간 이동

- P01 ⇄ P02 ⇄ P03 ⇄ P04: NavigationBar
- P01·P02·P03·P04 → P05: 항목 터치, Navigator.push
- P01·P02·P03·P04 → P06: 빠른 추가 FAB, BottomSheet
- 각 목록 → P07: 필터 Chip, BottomSheet
- 각 목록 → P08·P09·P10: 상단 ⋮ 상태 시연

## 구현하지 않는 기능

로그인, 회원가입, 결제, 푸시 알림, 추천 알고리즘, 영구 저장, 외부 유료 API, Provider/Riverpod/Bloc. 서버는 로컬 읽기 전용.
